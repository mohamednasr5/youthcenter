# نظام الحضور ومتابعة ولي الأمر — مركز شباب الأحمدية

يدعم النظام الأكاديميات الأربع:
- كرة القدم: `players` و`schedules`
- الكاراتيه: `karate_academy/players` و`karate_academy/schedules`
- الكونغ فو: `kungfu_academy/players` و`kungfu_academy/schedules`
- الإنشاد: `nasheed_academy/players` و`nasheed_academy/schedules`

## البنية

- `attendance-api/worker.js`: واجهة Worker للتحقق من الإدارة وحساب ولي الأمر وسجلات الحضور.
- `attendance-portal/`: بوابة ولي الأمر، وأدوات الحضور في لوحات الأكاديميات، وإدارة رموز المتابعة في لوحة المركز.
- بيانات الأكاديميات الأساسية تبقى في Firebase Realtime Database.
- أرقام أولياء الأمور وربطهم باللاعبين والرموز والجلسات وسجلات الحضور تحفظ في Durable Object خاص بالـ Worker، ولا تضاف إلى مسارات Firebase العامة.

## ربط Cloudflare Workers Builds

من مستودع `mohamednasr5/youthcenter` اختر الفرع:
`feature/attendance-guardian-portal`

الإعدادات:
- Root directory: جذر المستودع.
- Build command: `npm install` (لتثبيت Wrangler المحدد في package.json).
- Deploy command: `npx wrangler deploy`
- Preview command: `npx wrangler preview`
- ملف الإعداد: `wrangler.toml` في جذر المستودع.

بعد النشر سيظهر عنوان Worker على نطاق `workers.dev`. أضف العنوان إلى:
`attendance-portal/config.js`
بوضعه كقيمة `window.YC_ATTENDANCE_API` مع حذف الشرطة المائلة الأخيرة. يجب أن يكون العنوان على HTTPS.

## نشر قواعد Firebase

ملف `database.rules.json` يتضمن صلاحية القراءة العامة لبيانات فريق الإنشاد فقط، مع حصر الكتابة في حسابات الإدارة ذات Custom Claim الصحيح. مسارات أرقام أولياء الأمور والحضور لا تُضاف إلى Firebase.

لنشر القواعد وتحديث صلاحيات الإدارة:
1. تأكد من وجود GitHub Actions Secret باسم `FIREBASE_SERVICE_ACCOUNT_JSON` لخدمة مشروع `academia-e6d7b`.
2. افتح GitHub Actions.
3. اختر Workflow: `Deploy attendance database rules`.
4. اضغط Run workflow واختر الفرع `feature/attendance-guardian-portal`.
5. انتظر نجاح الخطوات كلها قبل تجربة لوحة الإنشاد.

هذا الـ Workflow ينشر قواعد قاعدة البيانات فقط ولا يعيد تهيئة حسابات الإدارة أو يبطل جلساتها. لا تستخدم Workflow القديم `Provision Firebase admins and deploy database rules` لهذا الغرض إلا عندما تريد أيضًا إعادة تعيين صلاحيات الحسابات؛ لأنه يجدد صلاحيات Custom Claims ويبطل جلسات تسجيل الدخول الحالية.

لا ترفع ملف Service Account إلى GitHub ولا ترسله في المحادثة.

## تهيئة أولياء الأمور

1. من لوحة الأكاديمية افتح قسم الحضور.
2. اختر اللاعب وأدخل رقم هاتف ولي الأمر بصيغة مصرية.
3. من لوحة المركز افتح «الحضور وأولياء الأمور».
4. أدخل الرقم نفسه وأنشئ رمزًا من 6 إلى 16 حرفًا أو رقمًا، ثم سلّمه لولي الأمر.
5. عند تغيير الرمز أو إلغائه تُرفض الجلسات القديمة مباشرة.

يمكن ربط رقم واحد بعدة لاعبين، حتى عبر أكاديميات مختلفة.

## الاختبار قبل الإطلاق

- اختبر `/api/health` من عنوان Worker.
- جرّب دخول إدارة مركز وحساب إدارة أكاديمية، وتأكد من رفض الحساب غير المصرح له.
- اربط رقم اختبار بلاعب في كل أكاديمية من الأربع.
- أنشئ رمز متابعة تجريبيًا، ثم تحقق أن ولي الأمر يرى اللاعبين المرتبطين بالرقم فقط.
- نفذ دخولًا وخروجًا عبر QR وتحقق من المدد والحالات.
- غيّر الرمز ثم جرّب الرمز القديم؛ يجب أن يُرفض.
- جرّب رقمًا واحدًا مرتبطًا بأكثر من لاعب وبأكثر من أكاديمية.

لا تعتبر الخدمة جاهزة للإنتاج قبل نجاح هذه الاختبارات بعد نشر Worker وقواعد Firebase.

## هوية اللاعب والباركود الآمن

- عند تحميل قائمة لاعبي الأكاديمية ينشئ الـ Worker لكل لاعب معرّف بطاقة عشوائيًا مستقلًا بصيغة `YC-...` ورمزًا عشوائيًا عالي العشوائية (256-bit).
- يحفظ سجل البطاقة وربطه باللاعب والأكاديمية واسم اللاعب ورقم ولي الأمر في Durable Object الخاص، مع فهرس للرمز.
- لا يحتوي QR نفسه على رقم هاتف ولي الأمر أو بيانات شخصية قابلة للقراءة؛ بل يحمل رمزًا عشوائيًا opaque لا يمكن تخمينه. تظهر بيانات اللاعب وولي الأمر على البطاقة المطبوعة/المعروضة فقط. يتحقق الخادم من الرمز ومن ربط اللاعب قبل تسجيل أي حركة.
- تغيير رقم ولي الأمر يحدّث بيانات البطاقة نفسها، وإلغاء الربط يمنع استخدام الرمز لتسجيل الحضور حتى يعاد الربط.
- مسار المسح الإداري: `POST /api/admin/scan` ويقبل `token` فقط. يتطلب Firebase ID token وصلاحية الأكاديمية المرتبطة بالبطاقة.
- أول قراءة تسجل حضورًا، والقراءة التالية بعد انقضاء 5 دقائق تسجل انصرافًا، ثم تتناوب الحركات. أي قراءة أخرى للاعب نفسه خلال 5 دقائق تُرفض دون تغيير سجل الحضور.
- عملية التبديل بين الحضور والانصراف تنفذ داخل Durable Object بتسلسل ذري لتقليل احتمالات تسجيل قراءتين متزامنتين كحركتين منفصلتين.
- تحفظ الجلسات المتعددة في اليوم داخل `sessions[]` حتى لا تمسح حركة دخول/خروج لاحقة الجلسة السابقة.
- تعرض بوابة ولي الأمر بطاقة QR نفسها الخاصة باللاعب المرتبط بحساب الأسرة، مع تنزيل PNG والطباعة ومشاركة الملف عبر قائمة المشاركة في الأجهزة التي تدعم مشاركة الملفات.

### إعداد تدفق التسجيل

1. أضف اللاعب من نموذج الأكاديمية المعتاد.
2. افتح قسم «هوية اللاعب والحضور الذكي» في لوحة الأكاديمية، واختر اللاعب وأدخل رقم ولي الأمر.
3. اضغط «حفظ بيانات اللاعب وإنشاء / تحديث QR». سيُنشأ الرمز أو يُحدّث ارتباطه ببيانات ولي الأمر، ثم تظهر البطاقة.
4. يمكن لولي الأمر رؤية البطاقة نفسها من بوابة متابعة الأسرة بعد تسجيل الدخول.

ملاحظة: حقل رقم ولي الأمر موجود حاليًا في قسم ربط اللاعب داخل لوحة الأكاديمية بعد إنشاء سجل اللاعب؛ وليس مدمجًا بعد داخل حقول نموذج إضافة اللاعب الأصلي لكل أكاديمية.

## التحديث: هوية QR الدائمة والحضور الذكي (نسخة ٢)

### نقاط النهاية الجديدة

| المسار | الطريقة | الوصف | الصلاحية |
|---|---|---|---|
| `/api/admin/qr-provision` | POST | إنشاء/تحديث بطاقة QR الدائمة تلقائيًا بعد حفظ لاعب جديد (+ ربط رقم ولي الأمر) | إدارة الأكاديمية / المركز |
| `/api/admin/qr-manage` | POST | `info` / `revoke` / `regenerate` — عرض حالة البطاقة، إيقافها، أو تجديد التوكن الآمن (نفس رقم الهوية) | إدارة الأكاديمية / المركز |
| `/api/admin/attendance-history` | GET | سجل الجلسات لكل لاعب حتى ٣١ يومًا مع هوية المدير المسجل لكل دخول/خروج | إدارة الأكاديمية |
| `/api/admin/transfer-player` | POST | نقل هوية اللاعب بين الأكاديميات مع الحفاظ على البطاقة نفسها (يُشترط إضافة اللاعب في لوحة الأكاديمية الهدف أولًا) | إدارة المركز فقط |
| `/api/admin/audit-logs` | GET | سجل تدقيق لكل حركة (مسح/ربط/إيقاف/تجديد/نقل) باسم المنفذ | إدارة المركز فقط |

### تحسينات الأمان والحضور

- **المسح عبر الأكاديميات**: أي لوحة أكاديمية مصرّح لها (ycFootball/ycKarate/ycKungfu/ycNasheed/ycAdmin/ycCenter) يمكنها مسح بطاقة أي لاعب؛ الحضور يُسجل دائمًا لأكاديمية اللاعب نفسها، ورقم الولي يظهر فقط لمدير الأكاديمية نفسها أو إدارة المركز.
- **التحقق قبل فحص التوكن**: يتم توثيق هوية الإدارة أولًا قبل البحث عن البطاقة.
- **حد معدل المسح**: ٤٠ عملية مسح لكل حساب في الدقيقة، مفروضة داخل Durable Object بشكل ذري (لا تتأثر بالعميل).
- **سجل التدقيق**: كل حركة مسح/ربط/إيقاف/تجديد/نقل تُوثَّق (نوع، أكاديمية، لاعب، منفذ، وقت) حتى ٦٠٠ عنصرًا.
- **دخول/خروج يدوي واعٍ بالجلسات**: التسجيل اليدوي من اللوحة يضيف/يغلق جلسات مصفوفة `sessions` دون الكتابة فوق تاريخ اليوم.
- **إيقاف البطاقة لا يُبعث تلقائيًا**: أي استدعاء لاحق (بوابة ولي الأمر أو قوائم اللاعبين) يحترم حالة `active:false` ولا يعيد تفعيل بطاقة موقوفة.
- **الهوية الدائمة**: تغيير رقم الولي أو تحديث بيانات اللاعب لا يغيّر التوكن؛ التجديد وحده يُصدر توكنًا جديدًا (نفس `barcodeId`) ويُبطل القديم فورًا.
